## 一、GPT-6.2 基本信息

老规矩，开头我们惯例先把基本信息过一下。这次是**两个模型**：

| 模型                | 官方定位              | API 编号          | 知识截止日期          |
| :---------------- | :---------------- | :-------------- | :-------------- |
| **GPT-6.2 Astra** | 给你最难的项目用的**前沿模型** | `gpt-6.2-astra` | 2026 年 5 月 18 日 |
| **GPT-6.2 Sol**   | 日常工作用的**高效模型**    | `gpt-6.2-sol`   | 2026 年 6 月 1 日  |

知识截止日期这次有更新。不过因为**后训练**的原因，所以实际了解的知识，会比这些日期**更往后延**一些。

GPT-6 Astra 当时是 4 月 30 日，这次往后推了**半个月到一个月**。我们当时测是否被灰度到新模型的时候，其实就是看的知识库日期——就是问"禁止联网，你知道 Fable5 吗"，就可以看出来是 GPT-6.1 还是灰度到 GPT-6.2 了。因为 GPT-6 Astra 和 GPT-6.1 Sol 其实都是**不知道 Fable5** 这个模型的。

![](https://upload.maynor1024.live/file/1794963683411__up_img.png)

价格上，**Astra 降价了 20%**。我简单做了一个表：

至少确实比以前便宜多了，不再是直接爆表了——我还记得 GPT-6 Astra 刚出的时候，我**一天就能用完一个 200 刀的 Pro 账号**的额度。

但除了价格，还有个必须看的衡量指标是**完成任务需要的 Token 数**。所以虽然你会看到 GPT-6.2 Astra 在定价上好像是要比 Claude Fable 5.2 贵，但如果你真的去用这两个模型，你会感觉到 **Claude Fable 5.2 消耗额度极其恐怖**——就是因为完成任务所需要的 Token 数差距太大了。这个我们在第二部分详聊。

## 二、GPT-6.2 的特点

这一次，OpenAI 依然延续老传统。因为确实在模型的智力和能力上打不过 Claude，所以整个模型的关键词，以及所有官方图表的横轴，都是同一个东西——**每个任务花多少钱**。

比如 **Agents' Last Exam**，这是一个测多步骤专业工作的评测，你可以理解成**给 Agent 的期末考**。

![](https://upload.maynor1024.live/file/1794963694628__up_img.png)

| 模型                | 得分      | 每任务成本      |
| :---------------- | :------ | :--------- |
| **GPT-6.2 Astra** | **78%** | **约 3 美元** |
| Claude Fable 5.2  | 73%     | 约 60 美元    |

**分数高了 5.5 分，成本只有对方的 5%。** 而跟自家上一代 GPT-6 Astra 比，分数高了 5.2 分，成本**不到三分之一**。

明明 Claude Fable 5.2 价格不是比 GPT-6.2 Astra 便宜吗，为啥最终差距能有这么多？秘诀就在于**消耗的 Token 量**。

![](https://upload.maynor1024.live/file/1794963694520__up_img.png)

从每项任务的输出 Token 量来看，GPT 其实非常恐怖，**Token 消耗极少**；而 Claude 为了追求更高的能力上限，会疯狂投入推理资源，每任务的 Token 输出甚至能**差到 7 倍**。

这也就解释了，为啥纸面价格上 Claude Fable 5.2 比 GPT-6.2 Astra 便宜，但 Claude Fable 5.2 却基本上是我们**烧不起**的程度，而 GPT-6.2 Astra 在实际 Token 消耗上反而要好一点。

比如我是 200 刀的 Pro 会员，跑了大概 **4 个视频和 3D 的 Case**、**2 个大方案的规划**以及**近百个代码审查**，跑之前我的周额度剩余 12%，这些跑完还剩 6%——也就是只消耗了 **6% 的周额度**。

![](https://upload.maynor1024.live/file/1794963699207__up_img.png)

而上次 Claude Fable 5.2，**10 个 Case 就烧掉了我近 30% 的周额度**，虽然效果远超 GPT，但也能看出来这个经济差异。

在官方 blog 里，其他任务也类似。比如 **Terminal-Bench-Science**，测的是模型在终端里做科研任务的能力——这是 GPT 的拿手好戏。我绝大多数做科研的朋友都反馈，GPT 几乎就是他们的科研主力模型，在做科研层面，**GPT 是一骑绝尘的**。

![](https://upload.maynor1024.live/file/1794963706493__up_img.png)

| 模型                | 得分      | 每任务成本      |
| :---------------- | :------ | :--------- |
| **GPT-6.2 Astra** | **77%** | **约 7 美元** |
| GPT-6 Astra（上一代）  | 68%     | 约 24 美元    |

OpenAI 也因此把 Astra 称为**世界上最适合科学家的模型**，第三方的 Vals 科学指数，它也确实是**第一**。

![](https://upload.maynor1024.live/file/1794963709590__up_img.png)

第三个是 OpenAI 内部的 **GDPval v2**，测的是咨询、金融、设计这些真实行业里的长程知识工作，结论也差不多——主打的就是一个**省钱**。

![](https://upload.maynor1024.live/file/1794963717875__up_img.png)

AA 的智能指数上，这一次进步还是明显的：**GPT-6.2 Astra 涨了 6 分，拿到 62 分，回到了第二的位置**；GPT-6.2 Sol 涨的不多，只涨了 2 分。

## 三、GPT-6.2 实测

接下来我也做了一些详细测试。首先是我自己最关心的——**模型的沟通能力和方案规划能力**，这在过去一直是 GPT 模型系列的短板。GPT 模型我自己的定位一直是**极其严谨、干活细致、绝不出错**，在后端、科研、审查层面能力极强，但在传统的项目方案规划（非科研）和**可读性**上，其实是比较差劲的。

那正好就有这么一个任务：最近很多朋友希望我在 AIHOT 的每一条新闻下面加一个**留言区**，方便大家交流。

![](https://upload.maynor1024.live/file/1794963728046__up_img.png)

![](https://upload.maynor1024.live/file/1794963736107__up_img.png)

这个事情其实远远不是加个留言功能这么简单。如果只是回帖评论，那就太简单了，麻烦的是**国内的合规问题和审查**：要加交流功能，就必须加**实名制**（也就是手机号登录），而手机号验证码很贵；更麻烦的是要有审查，必须**先审后发**，还得加审查机制等等。因为 AIHOT 只是我闲暇时间维护的一个**纯个人项目**，这个功能大家提了 2 个月，我一直很纠结——它对成本和风险都会大幅上升。

但它不影响测试。假设我们现在就要做这件事，到底应该怎么做？我让模型来给建议，这时候就能看出模型的规划和方案可读性问题了。我的 Prompt 特别简单，甚至都不能称为 Prompt：

> "最近已经收到很多用户的反馈，希望我们能在 AIHOT 中间加一个简单的留言区，方便大家来简单的交流。那基于这个背景，你可以帮我评估一下，如何在保证合规且安全的情况下，来以最小的成本去设计整个的留言与交流功能。"

![](https://upload.maynor1024.live/file/1794963735731__up_img.png)

在给大家看 GPT-6.2 Astra 的方案之前，先看一下 **Gemini 4 Carbon** 给我的方案规划（我最近很喜欢用这个模型 + Claude 一起出方案然后合并，Gemini 4 Carbon 真的很特别）。这个方案大概花了 **5 分钟**。

第一句话，就非常理解我的需求。

![](https://upload.maynor1024.live/file/1794963740271__up_img.png)

然后给我列出了**必须要遵守的合规项**，跟我了解到的完全一致。

![](https://upload.maynor1024.live/file/1794963740994__up_img.png)

然后给了一份**最小成本的设计方案**，非常棒，细节很多：不开放自定义昵称、不做多层盖楼、不开全量只开精选等等，在先审后发这块，**复用我们如今已经做好的 Agent 全自动新闻审查机制**。

![](https://upload.maynor1024.live/file/1794963749934__up_img.png)

最后给我做对比，以及问我选择。

![](https://upload.maynor1024.live/file/1794963749623__up_img.png)

**干干净净，极其清晰，并且有很多启发。** 中间可能会有部分幻觉，还需要 Claude 再审一道，但整体已经非常不错，主要是**可读性极强**，我能看得下去，有极强的实操性。

好，看完 Gemini 4 Carbon 的，再回来看 **GPT-6.2 Astra** 的。一共跑了 **24 分钟，是 Gemini 4 Carbon 的近 5 倍**，这是它的回复（上面几行基础的公司信息我就不放了，没什么意义）：

![](https://upload.maynor1024.live/file/1794963761796__up_img.png)

坦率的讲，明明很短，但我就是**读得云里雾里**，看完的感觉也是如看，**可读性极差**。并且里面居然说**前期建议是人工审核**——我是疯了吗？我每天无时无刻蹲在屏幕前审大家的评论？这是人能给出来的建议？排行榜的方案规划也是。

![](https://upload.maynor1024.live/file/1794963768873__up_img.png)

我甚至会觉得，GPT-6.2 Astra 的内容可读性和偏主动性的规划能力，好像比初期 GPT-6 Astra 的感觉还要差一些。在我手上有 Claude 和 Gemini 的情况下，我绝对不会愿意直接跟 GPT 沟通任务，**读它的反馈太累了**。

两家的方案规划对比如下：

| 对比项  | **Gemini 4 Carbon**  | **GPT-6.2 Astra**  |

| 可读性  | **极强、清晰有启发**         | **极差、读得很累**        |
| 合规项  | 列出必须遵守的合规项           | —                  |
| 审核建议 | 复用已有 Agent 审查机制、先审后发 | 建议人工审核（不切实际）       |
| 实操性  | **强**                | **弱**              |

然后是**代码审查**，这是我现在用 GPT 模型用得最多的地方。Claude 写完的代码，我都会有一个流程和脚本，自动让 GPT 审查最多 3 轮——因为 GPT 严谨的性格，会挑出很多问题和 BUG，防患于未然，这个非常棒。我以前的主力审查模型是 GPT-6.1 Sol Xhigh，这次 GPT-6.2 更新后，我用真实项目测了一下，也都是 xhigh 的推理强度，这块确实**有大进步**。在我自己构建的简易评测集中：

| **GPT-6.2 Astra** | **96%**（直接干满） |

## 写在最后

坦率的讲，GPT 系列的模型，已经逐渐开始**离普通人越来越远**了。

很多人都觉得，Claude 是做 ToB 的，GPT 才是 ToC 的。但是其实反了。**Claude 的模型，是真正意义上更适合普通人使用的**，包括现在的 Gemini 4 Carbon 模型也是这个趋势——它们会更易于沟通，更加主动地思考，去拓展你过去无法拓展的边界。

而 **GPT 模型，是真正意义上 To 精英的**：因为极其的严谨、听话，工业属性极重。对于我认识的科研和算法大佬来说，他们的反馈都是 GPT 模型使唤起来非常顺手，信息密度很高，做的实验非常严谨——可这样的模型，恰恰是不太适合普通人用的。

对于我自己来说，我依然觉得 GPT 的能力很强，特别是在一些严肃任务上，但是确实我太菜了，我的能力不足以让我指挥 GPT。所以想用好它，我自己的解法就是——**承认自己的菜逼，让 Claude 或者 Gemini 大人，帮我去指挥 GPT**，这样的体验反而极佳。

这可能，就是我目前认为的最优解吧。
